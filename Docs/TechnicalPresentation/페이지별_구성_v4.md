# 기술문서 구성 수정안

기존 24장에서 18장으로 압축. 제목 40.5pt, 본문 약 18pt, 핵심 설명 중심으로 정리.

| 페이지 | 제목 | 핵심 내용 |
|---|---|---|
| 01 | BUY, BID, BLOW | 세계관과 공간 설계 UI 구현과 연결 |
| 02 | 정보를 사고, 주식에 투자하는 게임 | 정보 경매와 거래에 사용할 현금을 함께 판단합니다. |
| 03 | 동화의 소재를 세 회사로 재해석 | 아기돼지 삼형제의 후일담을 금융 활동으로 옮겼습니다. |
| 04 | 외형으로 구분하는 캐릭터 역할 | 회사 운영자와 경매 진행자, 플레이어의 역할을 구분했습니다. |
| 05 | 1층 거래소와 2층 경매장 | 거래와 정보 획득을 오가도록 층별 기능과 동선을 설계했습니다. |
| 06 | 메인에서 배우고, 로비에서 준비 | 게임 설명과 참가 준비를 서로 다른 단계로 나눴습니다. |
| 07 | 고정 HUD와 상황별 UI | 항상 필요한 값은 상단에, 행동 안내는 상황에 맞춰 표시합니다. |
| 08 | 거래 전에 비용과 잔액 확인 | 예상값을 보여주고, 체결 결과로 현금·보유량·재고를 갱신합니다. |
| 09 | 공개·비공개 경매의 정보 구분 | 같은 조작 틀에서 공개 범위와 취소 조건을 구분했습니다. |
| 10 | 낙찰 정보는 개인 수첩에 기록 | 라운드와 회사의 교차점에서 보유 정보를 확인합니다. |
| 11 | 큰 단계 설명과 실제 UI 예시 | 한 페이지를 한 주제로 줄이고, 조작 순서를 크게 보여줬습니다. |
| 12 | 성공 결과를 화면과 소리로 전달 | 입력 신호와 서버가 확정한 성공 결과를 구분했습니다. |
| 13 | 경매 상태에 반응하는 상품·NPC | 게임 판정과 전시·애니메이션 연출의 책임을 분리했습니다. |
| 14 | 모든 화면에서 같은 설정 사용 | 메인·로비·인게임에 공통 옵션과 조작 규칙을 적용했습니다. |
| 15 | 최종 자산과 라운드별 변화 확인 | 순위와 함께 현금·주식 평가액, 경기 중 자산 흐름을 보여줍니다. |
| 16 | UI 입력과 서버 판정의 분리 | 화면은 요청을 보내고, 실제 자산 변경은 서버 결과를 반영합니다. |
| 17 | 본인 입찰 인상 시 차액만 예약 | 최고 입찰자가 다시 올릴 때 기존 예약금을 활용하도록 수정했습니다. |
| 18 | 회고와 다음 검증 | 세계관·공간의 의도를 실제 선택으로 연결 |

## 정리 원칙

- 담당 범위는 도입부의 발표자 노트로 통합
- HUD 원칙과 실제 HUD 설명을 한 페이지로 통합
- 컴포넌트 목록과 검증 조건은 관련 페이지의 발표자 노트에 유지
- 과거 밸런스 실험과 제작 도구 부록은 본문에서 제외
- 실제 게임 스크린샷과 편집 가능한 텍스트 유지
