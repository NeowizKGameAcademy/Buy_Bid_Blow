# LAN 직접 접속 구조

## 사용

1. Assets/Project/Scenes/SC_Lobby.unity를 열고 Play.
2. 호스트: 닉네임과 포트(기본 7777)를 입력하고 **방 만들기**.
3. 참가자: 닉네임, 호스트 PC의 **IPv4 주소**, 같은 포트를 입력하고 **접속**.
4. 같은 PC에서 테스트할 때만 localhost 또는 127.0.0.1을 사용합니다. 다른 PC에서 localhost를 입력하면 그 참가자 자신의 PC를 가리킵니다.
5. 연결/입장 처리 중에는 Esc 또는 접속 취소 버튼으로 취소할 수 있습니다. 실패 후 입력을 고쳐 다시 접속할 수 있습니다.
6. 호스트 화면 하단에 로컬 IPv4 후보와 UDP 포트가 표시됩니다. 여러 어댑터가 있으면 참가자와 연결된 LAN의 주소를 사용합니다.

LAN 통신에는 호스트의 해당 UDP 포트에 도달할 수 있어야 합니다. OS 방화벽/사설 네트워크 설정은 자동 변경하지 않습니다. 인터넷 릴레이, NAT 처리, 방 검색·방 코드, 호스트 이전은 이번 범위에 없습니다.

## 기능별 책임

| 코드 | 책임 |
|---|---|
| LobbyHud | 입력과 키보드 이동, 진행·실패·취소 UI, 플레이어 명패 표시. 접속은 ConnectionController에 요청. |
| ConnectionController | 접속 상태, 중복 요청 차단, 10초 타임아웃, 취소·나가기·오류 정리, Mirror 콜백을 UI 상태로 변환. |
| LobbyRoom | Mirror/KCP 시작·연결 콜백, 입장 메시지 송수신, 서버의 자리 배정·퇴장, 호스트 종료 알림, 서버 시작 조건 조회. |
| LobbyRoster | 서버의 6명 정원·입장 예약. 플레이어 생성 대기 중인 승인 요청도 포함해 동시 입장 초과 방지. |
| LobbyPlayer | 서버가 승인한 닉네임과 자리, 외형·준비 상태 SyncVar. 접속 완료 이벤트. |
| DirectConnectionSettings | IPv4/localhost와 1~65535 포트 검사, 로컬 닉네임·주소·포트 저장, 로컬 IPv4 후보 조회. |
| LobbyNickname | 클라이언트와 서버가 공유하는 닉네임 검사. |

## 상태와 승인 순서

Idle/Failed → Connecting → Joining → InRoom.
Connecting/Joining 취소 또는 나가기 → Stopping → Idle.
타임아웃·거절·연결 오류 → Stopping → Failed.
취소/실패 후 늦게 도착한 콜백은 Idle/Failed를 입장 상태로 바꾸지 않도록 검사합니다.

연결 직후 LobbyJoinRequest(protocol, nickname)를 전송합니다. 서버는 버전·닉네임·정원을 검사하고 자리를 예약합니다. LobbyJoinResponse 승인 후에만 Ready/AddPlayer를 보내며, 예약이 없는 AddPlayer는 거절합니다. 서버가 플레이어를 만들 때 승인한 이름을 SyncVar에 설정합니다. 로컬 플레이어 생성 완료를 확인해야 InRoom으로 전환합니다. 닉네임을 나중에 별도 Command로 다시 설정하지 않습니다.

게임 정원은 항상 6명입니다. Mirror 소켓 연결 한도는 10으로 두어 초과 접속자에게 거절 사유를 전달할 여유를 확보했습니다. 입장 예약과 실제 플레이어 수는 서버에서 6명을 넘지 않습니다. 10초 동안 플레이어 생성이 끝나지 않은 연결은 정리합니다. 종료된 연결의 예약도 반환합니다.

호스트가 나가면 종료 알림을 전송하고 짧게 송신 시간을 확보한 뒤 서버를 종료합니다. 예상치 못한 호스트 종료는 일반 연결 끊김으로 표시합니다. 호스트 이전은 하지 않습니다. CanStartMatch는 최소 3명, 모든 승인자의 플레이어 생성 완료, 전원 준비를 서버에서 검사합니다. 실제 게임 씬 전환은 기존과 같이 후속 작업입니다.

## 입력과 저장

Tab/Shift+Tab: 닉네임 → 주소 → 포트 → 방 만들기 → 접속.
Enter: 선택한 버튼 실행, 입력란에서는 다음 입력란 이동 후 접속.
N: 닉네임, J: 주소, H: 방 만들기. 입력 중에는 문자 단축키를 실행하지 않습니다.
Esc: 입력 포커스 해제 / 연결 중 접속 취소 / 입장 후 나가기.

닉네임·주소·포트는 PlayerPrefs에 저장합니다. 닉네임은 1~12 텍스트 요소, 앞뒤 공백 제거, 제어문자/각괄호 제외입니다. DNS 이름, URL, IPv6는 현재 직접 접속 입력 범위에 포함하지 않습니다. 닉네임 중복은 허용하며 플레이어 식별은 연결과 자리 기준입니다.

## 검증

Editor/DirectConnectionVerification.cs의 RunBatch가 UI 저장과 Play mode 네트워크 검증을 수행합니다. 독립 KCP 클라이언트 소켓에 Mirror 배치를 적용하여 실제 UDP로 입장 요청, Ready/AddPlayer, 응답을 주고받습니다. 별도 NetworkClient 싱글턴을 공유하지 않습니다.

검증 범위: IP·포트 경계값, 예약 정책, 호스트 생성, 독립 UDP 참가자의 이름/자리, 6개 자리, 7번째 거절, 버전 불일치, 퇴장 후 재입장, 호스트 종료 알림, 응답 없는 로컬 UDP 소켓을 이용한 타임아웃, 취소 후 정리, 호스트 재시작. 테스트 포트는 17777이며 테스트한 로컬 설정은 복원합니다.
