# 복권 장치 Sandbox

기존 `SC_ExchangeFurnished`를 복사한 별도 테스트 씬입니다. 원본 레벨과 플레이어 프리팹, 회사 거래 창구, 정보 경매, 하락 베팅, 라운드·결과 시스템을 재사용합니다. 원본 씬에는 복권 설정을 연결하지 않아 비활성입니다.

## 실행

1. `LotterySandbox.unity`를 열고 Play.
2. **로컬 호스트 시작 → 준비 완료 → 경기 시작**.
3. 다른 에디터/동일 Sandbox 클라이언트는 호스트 PC 주소를 입력해 **서버에 참가 → 준비 완료**. 모두 준비한 뒤 호스트가 시작합니다. 기본 KCP 포트는 7777이며 시작 후 신규 참가 불가입니다.
4. 1층 중앙의 금색 구체 복권 장치 `(0, 0, 5)`로 이동합니다. 장치를 바라보고 **E**를 누릅니다.
5. 마우스로 **− / + → 복권 구매**, 또는 **A/D(←/→)로 수량 선택 → E/Enter로 구매**. **Q / Escape / 닫기**로 패널을 닫습니다. 패널이 열린 동안 커서는 자동으로 표시·해제됩니다.
6. 모든 참가자에게 상단 추첨 결과가 10초간 나타납니다. 구매 패널에서도 마지막 결과를 확인합니다.

**빠른 시험**은 일반 15초 / 경매 30초(공개 10초, 비공개 10초, 자유 거래 10초)이며 13R·경매 2/6/10R 일정은 유지합니다. 첫 추첨은 경기 시작 후 45초, 이후 75초 간격입니다. 체크를 끄면 원래 60초 / 120초 설정을 사용합니다. 준비 시간 2초는 별도입니다. 인트로는 이 씬에서만 생략합니다.

씬이 없으면 `Tools > Buy Bid Blow > Lottery > Create and Open Sandbox`로 생성합니다. 기존 테스트 씬은 덮어쓰지 않습니다. 기존 Build Settings의 씬 목록은 변경하지 않았습니다. 이 씬을 별도 플레이어로 빌드할 때는 테스트용 Build Profile에 이 씬을 포함하세요. 원본 전용 서버 실행 파일에는 복권 설정이 없으므로, 그 서버에 접속하는 방식으로는 시험할 수 없습니다.

## 적용한 시험 규칙

| 항목 | 설정 |
|---|---|
| 추첨 | 2·6·10R 종료 시, 서버에서 회차당 한 번 |
| 추첨 번호 | 매회 1~100 전체에서 균등 추첨, 미판매 번호 포함 |
| 판매 기간 | 1~2R / 3~6R / 7~10R |
| 복권 가격 | 장당 $5 |
| 개인 한도 | 회차당 10장, 최대 $50 지출 |
| 기본금 | $30 → $50 → $70 |
| 판매금 | 100% 당첨금 적립 |
| 당첨 확률 | 개인 장수 ÷ 100. 타인 구매로 희석되지 않음 |
| 미당첨 | 미판매 번호가 뽑히면 당첨자 없음. 기본금과 판매 적립금을 전액 이월 |
| 다음 회차 | 이월액 + 해당 회차의 새 기본금 + 새 판매금 |
| 당첨 | 당첨자 한 명에게 전액 지급, 다음 회차 이월액 0 |
| 복권 초기화 | 당첨 여부와 무관하게 매회 전량 소멸·재판매 |
| 취소 | 구매 즉시 차감, 취소·환불 불가 |
| 무구매 | 당첨자 없이 기본금까지 이월 |
| 마지막 미당첨 | 미지급 잔액으로 표시. 경기 간 이월·자산 정산 반영 없음 |
| 공개 정보 | 전체 판매량·당첨금 구성·본인 장수·확률. 타인별 장수 비공개 |
| 이탈 | 경기 참가자의 구매권은 유지, 당첨금도 해당 참가자 포트폴리오에 지급. 현재 프로젝트는 진행 중 신규 입장이 차단되므로 재접속 복구 UI는 추가하지 않음 |

예: 1회차 2장 판매 후 미당첨이면 $30 + $10 = $40 이월. 2회차 새 기본금 $50이 더해져 판매 전 당첨금 $90. 당첨자가 나오면 다음 회차에는 그 회차 기본금부터 시작합니다.

전체 100장과 개인 10장 제한은 별개입니다. 6명이 모두 한도 구매해도 판매량은 60장이므로 최소 40개는 미판매 번호입니다. 이는 확정 당첨보다 누적을 자주 보는 시험 설정입니다. 현금이 부족한 플레이어는 가진 현금을 모두 쓸 수도 있으므로, 개인 한도는 절대적인 잔액 보장 규칙은 아닙니다.

## 설정과 구현 경계

- `LotterySettings.json`: 용량·가격·개인 한도·기본금·증가액. 다음 경기부터 적용됩니다.
- `Rules/`: 별도 Systems asmref. Unity·Mirror 의존 없이 구매·추첨·이월 판정.
- `Runtime/`: 별도 Game asmref. 서버 요청·상태 전송, 장치 상호작용, 임시 IMGUI 구매 패널.
- 서버가 금액과 당첨 결과를 확정합니다. 구매는 입찰 예약금을 제외한 현금으로만 가능하며 서버 거리 검사(4.5m)와 착석 검사도 적용합니다.
- 요청에 회차 번호 포함. 마감 이상·지난 회차·잘못된 수량·한도 초과는 전체 거절합니다.
- 추첨은 경매·하락 베팅 정산 뒤, 자산 이력 기록 전에 처리합니다. 당첨금이 기존 현금·총자산·결과에 반영됩니다.
- 복권 난수는 주가·정보 상품의 난수와 분리합니다. 복권을 켜도 같은 시드의 기존 주가가 바뀌지 않습니다.
- UI는 매회 본인 장수와 전체 상태를 서버로부터 받습니다. 표시 확률의 분모는 판매량이 아닌 고정 번호 수입니다.
- 공용 변경은 MatchEngine의 선택적 복권 연결, GameNetworkManager의 선택적 메시지·정산 연결, PlayerInteraction의 기존 IInteractable 처리 추가입니다.

## 검증

- 2026-10-28: 복권·기존 경매·라운드 EditMode 49개 통과, 실제 Sandbox 호스트 PlayMode 1개 통과. 구매 패널과 장치 화면을 캡처해 확인했습니다. 별도 PC의 원격 클라이언트 접속은 이번 자동 검증에 포함하지 않았습니다.
- EditMode `LotteryTests`: 미판매 번호, 번호 경계, 기본금·판매금 이월, 복권 소멸, 개인·전체 한도, 입찰 예약금 보호, 마감과 지난 회차 거절, 중복 지급 방지, 기존 주가 유지, 최종 자산 이력.
- PlayMode `LotterySandboxTests`: 실제 복사 씬의 호스트·준비·시작·구매·현금 차감·추첨 메시지·다음 회차 초기화.
- 결과 파일과 테스트 로그는 `Library/Lottery*Results.xml`, `Library/Lottery*Tests.log`에 생성합니다.

현재 버전은 기술·플레이 확인용입니다. 장치 모델, 구매 패널, 결과 알림은 임시 표현입니다.
