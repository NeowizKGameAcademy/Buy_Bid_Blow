# 주식 뽑기머신 Sandbox

기존 LotterySandbox를 **StockGachaSandbox**로 이름을 바꾸고, 같은 거래소 레벨·캐릭터·거래·정보 경매·하락 베팅·라운드 시스템을 유지한 채 기계 기능을 교체했습니다. 원본 빌드 씬과 경기 설정은 변경하지 않습니다. 기존 씬 GUID와 스크립트 메타 GUID를 유지합니다.

## 실행

1. `StockGachaSandbox.unity` 열기 → Play.
2. **로컬 호스트 시작 → 준비 완료 → 경기 시작**.
3. 다른 플레이어는 같은 Sandbox에서 서버 주소로 참가 → 준비 완료. 모두 준비한 뒤 호스트가 시작합니다.
4. 1층 중앙의 금색 뽑기머신 `(0,0,5)`을 바라보고 **E**.
5. **한 번 뽑기** 버튼을 클릭하거나 **E / Enter**로 한 번씩 뽑습니다.
6. **Q / Escape / 닫기**로 돌아갑니다. 패널이 열린 동안 마우스 커서는 해제됩니다.

Play 중 기계를 열었던 E 입력이 곧바로 결제되지 않도록 첫 프레임은 건너뜁니다. 응답을 기다리는 동안 다음 결제는 막지만, 회차·라운드별 이용 제한은 없습니다.

행동 시간을 확보하기 위해 일반 90초 / 경매 150초(공개60·비공개30·자유행동60)로 진행합니다. 총 13R, 경매 2·6·10R, 기본 경기 시간 22분 30초이며 준비 5초는 별도입니다. 인트로는 Sandbox에서만 생략합니다.

씬 생성·열기 메뉴: `Tools > Buy Bid Blow > StockGacha > Create and Open Sandbox`.
외부 서버/클라이언트는 동일한 Sandbox 빌드를 사용해야 합니다. 원본 전용 서버 빌드에는 이 기능이 활성화되어 있지 않습니다. 기존 Build Settings는 수정하지 않았습니다.

## 확정한 시험 규칙

| 항목 | 적용 |
|---|---|
| 가격 | 1회 $20 — 기존 게임 통화 표시 유지 |
| 초기 상품 | 꽝 90개 + Straw 20주 + Timber 20주 + Brick 20주 |
| 재고 | 모든 참가자가 하나의 150개 재고를 공유 |
| 추첨 | 서버가 남은 항목 중 한 개를 균등 추첨, 즉시 결과 제공 |
| 초기 확률 | 꽝 60%, 주식 합계 40% (회사별 약 13.33%) |
| 현재 확률 | 항목별 남은 수량 / 전체 남은 수량 |
| 주식 당첨 | 해당 주식 1주를 즉시 포트폴리오에 지급 |
| 꽝 | 주식 지급 없이 $20 지출, 꽝 재고도 1개 소모 |
| 시장 | 시장과 별도 초기 재고. 당첨 주식을 시장에 매도하면 시장 재고에 추가 |
| 이용 | 모든 진행 라운드에 이용 가능, 개인·라운드별 횟수 제한 없음 |
| 종목 제한 | 한 종목 또는 꽝만 남아도 작동 |
| 소진 | 150개 소진 시 결제·추첨 중단 |
| 재충전 | 라운드·경매에서 보충하지 않음. 새 경기에서만 초기화 |
| 결과 | 본인 패널에 결제 결과, 전체 참가자에게 결과 알림 4초 |
| 자산 | 획득 주식은 매매·평가·최종 순위에 일반 보유 주식과 동일하게 반영 |
| 폐기 규칙 | 복권 회차·예약 추첨·기본금·당첨금·이월 모두 제거 |

예: 꽝이 1개 나오면 남은 수량은 꽝139·회사별20, 총199개. 다음 꽝 확률은139/199, 각 주식 확률은20/199로 갱신합니다.

## 구조

- `StockGachaSettings.json`: 가격·꽝 개수·회사별 초기 수량. 새 경기부터 적용.
- `Rules/StockGachaGame.cs`: 순수 C#의 공용 유한 재고, 현금 차감·주식 지급.
- `Rules/MatchEngine.StockGacha.cs`: 경기 시간·참가자 검사 및 기존 포트폴리오 연결.
- `Runtime/GameNetworkManager.StockGacha.cs`: 경기별 세션과 요청 번호 검사, 서버 구매, 개인 지갑 및 공용 재고 동기화.
- `Runtime/StockGachaSandboxPanel.cs`: 연결·구매 UI, 현재 수량·확률, 커서·키보드 조작.
- 서버는 거리(4.5m)·착석·진행 상태·입찰 예약금 제외 현금을 검사합니다.
- 같은 요청 번호는 다시 결제하지 않으며, 이전 경기의 요청도 거절합니다.
- 별도 난수를 사용하므로 기존 주가 및 정보 생성 결과에 영향이 없습니다.
- 재고 소모와 결제·지급은 검증 후 함께 처리됩니다. 잔액 부족·소진·잘못된 요청에는 재고나 현금 변화가 없습니다.

## 2배 경제 규모 시험

검증: 2배 규모·기존 경매·라운드 규칙 테스트 52개와 실제 호스트 실행 테스트 2개 통과. 거래창의 상승 확률 표시와 뽑기 HUD 중첩 해제도 화면으로 확인했습니다.

Sandbox 전용 MatchSettings.json을 사용합니다. 원본 Content/Match/MatchSettings.json은 유지합니다.

- 시작 현금: 200 → 400.
- 초기 주가: 기존 난수 추첨 결과 ×2. Straw 24~50 / Timber 38~62 / Brick 50~76.
- 주가 하한: 5 → 10. 거래창의 하락 베팅 하한 판정도 서버 설정을 따릅니다.
- 시장 재고: 인원 ×10 +10주. 3인 회사별40주 / 6인 회사별70주.
- 가챠: 20원, 꽝90개·회사별20주, 총150개.
- 라운드 시간은 각각 30초 연장했습니다. 주가 변동폭과 상승 확률(35%·50%·75%)은 그대로입니다.
- 거래창 회사 이름 아래에 서버에서 전달받은 상승 확률을 표시합니다.

## 알바 가격 보정 연결 준비

운반 블록·폭탄·작업장·급여 지급은 아직 미구현입니다. 이번 변경은 서버에서 연결할 가격 보정 처리만 추가합니다.

- MatchEngine.AddRoundPriceAdjustment: 회사 블록 +1, 폭탄 -3을 받습니다. 현재 라운드만 순보정 ±5원 한도 적용.
- 상승은 최소 +1, 하락은 최소 -1, 보합은 0. 다음 라운드에서는 보정 수치가 초기화되며 실제 변동한 주가는 유지됩니다.
- 마감 전까지 공개 주가는 고정입니다. 현재 보정으로 이후 주가가 바뀌어도 미리 판매한 미래 정보의 방향을 유지합니다.
- 하한 부근에서는 다음 상승 전까지 예정된 하락 횟수만큼 최소 여유를 남깁니다. 이 때문에 실제 적용 금액은 요청 보정액보다 작을 수 있습니다.
- 보정 메서드는 현재 클라이언트에 노출하지 않았으며, 추후 서버 운반물 검증 후 호출할 예정입니다.
- 검증: Systems 코드를 별도 컴파일해 500개 시드 ×13라운드에서 방향 고정·하한·라운드 초기화·90/150초 설정을 확인했습니다(291,510개 판정 통과). 운반 씬의 플레이 테스트를 뜻하지 않습니다.
